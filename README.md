## Быстрый запуск в Windows с XAMPP

Нужны PHP 8.1+ с PDO MySQL и MariaDB 10.4+ либо MySQL 8.0.16+. В XAMPP кнопка **MySQL** обычно запускает MariaDB.

1. Распакуйте папку `lab8`, например в `C:\lab8`. Запустите **MySQL** в панели XAMPP. Для импорта через phpMyAdmin запустите также **Apache**.
2. Откройте `http://localhost/phpmyadmin`. Создайте **новую пустую** базу `lab8_iot` с кодировкой `utf8mb4` и сравнением `utf8mb4_unicode_ci`. Выберите её и импортируйте `sql/schema.sql`. Скрипт не удаляет существующие таблицы; повторно импортировать его в заполненную базу не нужно.
3. Скопируйте `config/local.example.php` в `config/local.php`. Для первоначального заполнения временно укажите установочную учётную запись MySQL, например `root` и её реальный пароль. Если пароль root в вашей локальной установке пустой, укажите пустую строку. Порт по умолчанию 3306; если в XAMPP он другой, исправьте DSN.
4. Откройте **PowerShell**, выполните:

```powershell
cd C:\lab8
& C:\xampp\php\php.exe bin\seed.php
```

Будут созданы три пользователя и три устройства. Повторный запуск заполнения непустой базы отклоняется. У пользователей `nastya`, `viewer`, `other` учебный пароль `Demo_251361!`. У `nastya` два устройства, у `other` третье, у `viewer` право просмотра первого.

5. В `sql/grants.example.sql` замените учебный пароль служебной учётной записи на свой и выполните скрипт через SQL в phpMyAdmin. Он рассчитан на имя базы `lab8_iot` и подключение `127.0.0.1`. Если имя или адрес изменены, исправьте и GRANT. Триггеры создаёт установщик, затем веб-приложение работает с ограниченными правами.
6. В `config/local.php` замените установочную учётную запись на `lab8_app` и выбранный пароль. Эта запись не может удалять журналы, создавать таблицы или снимать блокировки.
7. Запустите PHP из PowerShell:

```powershell
& C:\xampp\php\php.exe -S 127.0.0.1:8080 -t public
```

Оставьте окно открытым. Откройте **http://127.0.0.1:8080/login.php**. Войдите как `nastya` с учебным паролем. Веб-корень: именно `public`, а не вся папка проекта. Конфигурация, сессии, ключи и тестовые скрипты не должны быть доступны из браузера. В Apache настройте отдельный VirtualHost с `DocumentRoot C:/lab8/public`, если хотите запускать через Apache вместо встроенного сервера PHP. Нельзя просто положить весь проект в `htdocs` и открыть его корень.

## Имитация устройства без оборудования

В другом окне PowerShell:

```powershell
cd C:\lab8
& C:\xampp\php\php.exe bin\simulator.php http://127.0.0.1:8080 1 216 0
& C:\xampp\php\php.exe bin\simulator.php http://127.0.0.1:8080 2 184 1
```

Это первое устройство с 21,6 °C и выключенным реле и второе с 18,4 °C и включённым реле. Обновите страницу. Нажмите «Включить реле» у первого устройства. Повторный запрос симулятора вернёт `COMMAND 1 EOC`. Чтобы имитировать исполнение команды, отправьте `Rele=1`:

```powershell
& C:\xampp\php\php.exe bin\simulator.php http://127.0.0.1:8080 1 216 1
```

Без температуры и реле запрос выполняет проверку связи:

```powershell
& C:\xampp\php\php.exe bin\simulator.php http://127.0.0.1:8080 1
```

При первом обращении без заданной команды ответ `COMMAND ? EOC`. Сервер не переключает физическое реле сам: он сохраняет команду, а устройство получает её в ответ на свой очередной запрос.

## Протокол устройства

`POST /device_status.php`, тело JSON `{ "Term": 216, "Rele": 0 }`. `Term`: целое число десятых долей градуса в диапазоне −550…1250; `null` означает отсутствие показания датчика. `Rele`: целое 0 или 1. Оба поля можно опустить, передав `{}`. Заголовки:

```text
Content-Type: application/json
X-Device-UID: 32 шестнадцатеричных символа
Authorization: Bearer 64 шестнадцатеричных символа
```

Реквизиты создаёт `seed.php` в `var/demo_credentials.json` **вне веб-корня**. UID является идентификатором, секретный токен подтверждает право устройства. В базе хранится только SHA-256 случайного 256-битного токена. Пользовательский пароль защищается отдельным медленным `password_hash`. GET с одним ID больше не разрешён. Для реального удалённого обмена нужен HTTPS, а локальный HTTP используется только для демонстрации.

## Как работают ограничения

* Пользователь: не более 10 обращений за фиксированное окно 60 секунд для пары пользователь-устройство. Считаются просмотр карточки, история, корректная команда. На 11-м обращении триггер ставит блокировку на 60 секунд. У других устройств и других пользователей независимые счётчики.
* Устройство: не более 30 корректных запросов с действительным токеном за фиксированное окно 60 секунд. На 31-м триггер блокирует его на 60 секунд; запросы получают HTTP 429 и не меняют показания. Пользователь видит предупреждение.
* Запросы во время блокировки её не продлевают. После истечения доступ восстанавливается при следующем запросе. Окно начинается с первого запроса и не является скользящим. Неверные реквизиты и невалидные данные в эти счётчики не входят.
* Главная страница делает одно обращение для каждой карточки. Успешная команда перенаправляет на неё и вызывает очередной просмотр; поэтому число событий больше числа нажатий кнопок.

Пороги выбраны для учебной демонстрации: в задании конкретные числа не заданы. Во время защиты не обновляйте страницу слишком часто. Если блокировка появилась, подождите 60 секунд. Для быстрого сброса **только в учебной базе** администратор может выполнить:

```sql
UPDATE device_access SET window_start=NULL,request_count=0,blocked_until=NULL;
UPDATE devices SET window_start=NULL,request_count=0,blocked_until=NULL;
```

## Проверки

Проверено на PHP 8.4 и MariaDB 11.8. Автотесты включают права доступа, команды и фактическое реле, историю, оба триггера и границы порогов, истечение блокировок, SQL-инъекции, CSRF, ограничения БД, параллельные сессии БД, JSON и HTML. Результат: `docs/test_results.txt`.

Тесты очищают журналы и сбрасывают состояния **в отдельной тестовой базе**. Не запускать на рабочих данных. Сначала заполните отдельную базу `seed.php`, затем настройте конфигурацию приложения на неё. Файл конфигурации администратора той же тестовой БД должен лежать вне `public`. Пример PowerShell при установленном Python 3:

```powershell
$env:PHP_BIN='C:\xampp\php\php.exe'
$env:LAB8_TEST_CONFIG='C:\lab8\config\test-admin.php'
python tests\run.py http://127.0.0.1:8080
```

`test-admin.php` возвращает такой же массив, как `local.example.php`, с реквизитами администратора тестовой базы. Для теста прав в `local.php` должна оставаться ограниченная запись `lab8_app`. Для тестирования базы с другим именем измените область GRANT в `grants.example.sql`. В папке `var` должен быть файл реквизитов, полученный заполнением именно этой базы.

## Состав

* `public`: только доступные из браузера PHP-страницы и CSS.
* `app/db.php`: подключение и параметризованные запросы; `app/service.php`: операции в транзакциях.
* `app/templates`: общий шаблон и отдельная карточка устройства.
* `sql/schema.sql`: таблицы, VIEW и два триггера; `sql/grants.example.sql`: права служебной записи.
* `bin`: заполнение демонстрационных данных и симулятор устройства.
* `tests`: воспроизводимые интеграционные тесты.

Теоретические меры HTTPS, шифрования резервных копий, сетевого экрана и отдельного ограничения частоты неуспешных входов требуют настройки инфраструктуры. Приложение демонстрирует перечисленные в отчёте механизмы, но не заменяет защиту сервера от массового сетевого трафика.
